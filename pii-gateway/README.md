# PII-шлюз (первичная запись данных гостей в РФ)

Небольшой сервис на вашем собственном сервере (Ubuntu 22.04, Москва) —
первичная запись имени/телефона гостя в локальный PostgreSQL, с
зеркалированием тех же данных в Firestore проекта `hoocah-pos` сразу после
сохранения. Зачем это вообще нужно и что именно закрывает (а что
сознательно не закрывает) — см. docstring в начале
[`server.js`](server.js) и раздел 7 политики конфиденциальности платформы
(`saas/console/console.js`, `screenLegalPrivacy`).

**Область Phase 1**: только имя и телефон гостя, только в момент, когда
гость сам их сообщает (подтверждение SMS-кода, сохранение профиля в
приложении, форма брони, правка телефона в админском экране «Гости»).
Мид-смена (касса во время оплаты) и коллекции `reservations`/
`discountCards`/`waitlist` со своими независимыми копиями имени/телефона —
не в этой фазе.

## Установка (на самом сервере, через SSH — Termius/Termux/что угодно)

Подключитесь к серверу (`ssh root@<IP-сервера>`), скопируйте туда эту
папку целиком (например, через `git clone` репозитория или `scp`), затем:

```bash
cd pii-gateway
./setup.sh
```

Скрипт сам: поставит PostgreSQL и Node.js 20 (если их ещё нет), создаст
пользователя и базу `pii_gateway`, применит схему (`schema.sql`), скопирует
сервис в `/opt/pii-gateway`, спросит пароль для базы и сервисный аккаунт
Firebase — и запустит всё как systemd-сервис (`pii-gateway`).

По ходу скрипт попросит:
1. **Пароль для пользователя базы** — придумайте сами, без кавычек/`$`.
2. **Сервисный аккаунт Firebase проекта `hoocah-pos`** (не `saas-3bdc8`!)
   в base64 одной строкой. Получить:
   - Firebase Console → проект `hoocah-pos` → Project settings → Service
     accounts → Generate new private key → скачается JSON-файл.
   - На сервере (или там, где лежит файл): `base64 -w0 файл.json` — вывод
     скопировать и вставить в скрипт как есть.

В конце скрипт сам проверит себя (`curl http://127.0.0.1:8080/health`) —
если увидите `{"ok":true}`, сервис запущен.

## TLS (HTTPS) — нужен домен

Сервис слушает только `127.0.0.1:8080` — наружу его открывает `nginx` с
настоящим TLS-сертификатом (мобильное приложение подключается по
`https://`, без шифрования тут нельзя — данные гостя не должны идти
открытым текстом). Для нормального Let's Encrypt-сертификата нужен
**домен** (A-запись, указывающая на IP этого сервера) — на голый IP
сертификат не выпустить.

**Если домена ещё нет** — этот шаг пока пропустить, есть варианты:
поддомен на уже имеющемся у вас домене (например `pii.вашдомен.ru`), либо
бесплатный поддомен (DuckDNS и т.п.). Скажите, что у вас есть, и настрою
`nginx`/`certbot` под конкретный случай.

Когда домен определится, команды будут примерно такие (уточню точно под
ваш случай):

```bash
apt-get install -y nginx certbot python3-certbot-nginx
# nginx: reverse proxy 443 -> 127.0.0.1:8080, certbot сам добавит TLS
certbot --nginx -d pii.вашдомен.ru
```

## Прописать URL в сборку приложения

`PII_GATEWAY_URL` — `https://pii.вашдомен.ru` (после настройки TLS выше).
Заводится как секрет репозитория на GitHub (Settings → Secrets and
variables → Actions → New repository secret, имя `PII_GATEWAY_URL`) — обе
сборки (`build-apk.yml` и `saas-on-demand-build.yml`) уже настроены его
подхватывать.

Для локальной сборки/отладки — тот же флаг напрямую у `flutter run`/
`flutter build`: `--dart-define=PII_GATEWAY_URL=https://...`.

## Проверка перед боевым использованием

- `npm test` (в папке `pii-gateway`) — smoke-тест валидации входа, реально
  поднимает HTTP-сервер и шлёт ему запросы, не требует живой БД/Firebase.
- `systemctl status pii-gateway` и `journalctl -u pii-gateway -f` — статус
  и логи сервиса на сервере.
- Полноценно проверить весь путь (SMS-код → шлюз → Postgres → Firestore →
  касса видит гостя) можно только вручную на реальном стенде — сделайте
  это хотя бы один раз перед тем, как выкатывать сборку с новым
  `PII_GATEWAY_URL` на реальные заведения.

## Резервное копирование

Скрипт не настраивает бэкапы Postgres — база крошечная (десятки-сотни MB
даже при 10+ заведениях, см. оценку в чате), проще всего добавить простой
`pg_dump` по cron:

```bash
echo '0 3 * * * postgres pg_dump pii_gateway | gzip > /var/backups/pii_gateway-$(date +\%F).sql.gz' \
  | tee /etc/cron.d/pii-gateway-backup
```
