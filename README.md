# Hookah POS

Приложение для управления столами кальянной: карта зала, таймер визита 1.5ч
с перезабивкой, меню, скидочные карты, сотрудники, склад с инвентаризацией
и отчёты по выручке.
Без кассового аппарата и фискализации — только учёт заказов внутри
открытого счёта и онлайн-отчёты вместо Z-отчёта.

## Что внутри

- `lib/models` — модели данных (стол, сеанс/счёт, меню, скидочная карта,
  сотрудник, позиции склада/движения/инвентаризация)
- `lib/services/firestore_service.dart` — вся логика работы с Firestore
- `lib/services/auth_service.dart` — анонимный вход в Firebase (нужен только
  для доступа к базе; реальный вход в приложение — по PIN-коду сотрудника)
- `lib/screens/login_screen.dart` — вход по 4-значному PIN
- `lib/screens/setup_required_screen.dart` — экран-подсказка, который
  показывается вместо краха, если Firebase ещё не настроен
- `lib/screens/employee/*` — интерфейс сотрудника: карта зала, экран стола
  (таймер, перезабивка, обновление таймера, скидочная карта, заказ с
  изменением количества позиций), поиск по меню
- `lib/screens/admin/*` — админка: отчёты, редактор карты зала (drag&drop
  столов), меню, скидочные карты, сотрудники, склад (произвольные позиции
  с любой единицей измерения — граммы табака, мл/л напитков, штуки банок и
  т.п.; приход/списание/корректировка с историей движений; инвентаризация
  остатков с фиксацией расхождений)
- `firestore.rules` — правила безопасности Firestore (закрытые счета
  нельзя редактировать или удалить — это защищает отчёты)
- `.github/workflows/build-apk.yml` — сборка APK в GitHub Actions.
  Папки `android/`, `ios/` и т.п. в репозитории **намеренно нет** — CI сам
  генерирует их при каждой сборке той версией Flutter, которая только что
  установлена на раннере, это исключает рассинхрон версий Gradle/AGP

## Как запустить (пошагово)

### 1. Подключить Firebase

```bash
dart pub global activate flutterfire_cli
flutterfire configure
```

Команда попросит выбрать/создать проект в Firebase и сама перезапишет
`lib/firebase_options.dart` настоящими ключами. Выберите платформу Android.

Если запустить приложение до этого шага — оно не упадёт, а покажет экран
с этой же инструкцией на русском (см. `SetupRequiredScreen`).

В консоли Firebase:
- Включите **Firestore Database** (production mode)
- Включите **Authentication → Sign-in method → Anonymous**
- Вставьте содержимое `firestore.rules` в Firestore → Rules

### 2. Задать ключ заведения (обязательно)

POS и гостевое приложение «Колибри Лаундж» входят в Firebase анонимно, и по
самому факту входа отличить кассу от телефона гостя нельзя. Поэтому правила
считают «персоналом» только устройства с документом `staffDevices/{uid}`, а
создать его можно, лишь назвав ключ заведения.

Создайте его один раз в Firestore вручную — коллекция `meta`, документ
**staffSecret**, поле `value` (строка) с любым паролем:

```json
{ "value": "ваш-пароль-от-рабочих-планшетов" }
```

**Без этого документа зарегистрировать планшет невозможно**, и вход по PIN
будет отклоняться: касса не сможет прочитать даже список сотрудников.

При первом запуске POS сам покажет экран «Рабочее устройство» и попросит
этот ключ. Вводится один раз на планшет.

### 3. Создать первого администратора

Пока сотрудников нет — некому зайти в админку. Проще всего один раз
вручную добавить документ в Firestore:

Коллекция `employees`, документ (любой id):
```json
{
  "name": "Владелец",
  "pinCode": "0000",
  "role": "admin"
}
```

Дальше всех остальных сотрудников и вторых админов можно добавлять уже
из самого приложения (раздел «Сотрудники» в админке).

### 4. Залить в GitHub и собрать APK

```bash
git init
git add .
git commit -m "Initial commit"
git remote add origin <ваш_репозиторий>
git push -u origin main
```

Workflow `.github/workflows/build-apk.yml` соберёт release-APK автоматически
при пуше в `main` (или вручную через вкладку Actions → Run workflow).
Готовый файл будет доступен в разделе **Actions → (последний запуск) →
Artifacts → hookah-pos-apk**.

Первая сборка займёт больше времени (~10–15 минут, скачивание Flutter SDK
и Android-зависимостей), следующие — заметно быстрее за счёт кэша.

## Логика таймера

- При старте сеанса `plannedEnd = сейчас + 90 минут`.
- «Перезабивка» полностью сбрасывает `plannedEnd` на новые 90 минут и
  увеличивает счётчик `refillCount` (история хранится в `refillHistory`).
- «Обновить таймер» — точечная корректировка (+15/+30/+60 или −15 минут)
  без сброса счётчика перезабивок — для случаев, когда просто нужно
  чуть добавить время.
- Таймер считается локально на каждом устройстве от `plannedEnd`,
  хранящегося в Firestore, поэтому все телефоны сотрудников показывают
  одинаковое время без доп. нагрузки на базу.
- Цвета: зелёный (свободен) → синий (идёт сеанс) → оранжевый (осталось
  < 15 мин) → красный (время вышло).

## Отчёты вместо кассы

Раздел «Отчёты» в админке — единственный источник финансовых цифр, раз
кассы в приложении нет. Считается по закрытым счетам за период
(сегодня / 7 дней / 30 дней / свой период):

- выручка, количество визитов, средний чек, количество перезабивок;
- разбивка по сотрудникам (кто сколько выручки принёс);
- популярные позиции меню;
- сколько раз применялись скидочные карты и на какую сумму.

Кнопка «Копировать отчёт текстом» кладёт сводку в буфер обмена — удобно
переслать в мессенджер, если нужно показать цифры кому-то ещё.

Закрытый счёт (`status == 'closed'`) больше нельзя изменить или удалить —
это закреплено в `firestore.rules`, чтобы отчёты нельзя было подделать
задним числом даже через прямой запрос к базе.

## Чего в приложении сознательно нет

- Кассового аппарата, фискализации, приёма оплаты — только список
  позиций и сумма для ориентира персонала, и отчёты вместо Z-отчёта.
- Полноценной системы ролей/прав Firebase Auth — вход по PIN упрощён
  специально для маленького заведения с доверенным персоналом. Роль
  проверяется внутри приложения, а не на уровне Firebase Auth (она
  анонимная и общая для всех) — учитывайте это при выборе, кому доверять
  устройства с установленным приложением.

## Если APK не открывается или зависает на загрузке

- **Приложение сразу закрывается** — почти всегда это значит, что шаг
  «Подключить Firebase» ещё не сделан или сделан с ошибкой. Начиная с этой
  версии приложение в такой ситуации не крашится, а показывает инструкцию
  на экране — если у вас старая сборка, пересоберите APK.
- **Экраны вечно крутят загрузку** — проверьте, что в консоли Firebase
  включены и Firestore, и Anonymous-вход, и что `firestore.rules`
  опубликованы.
- **Сборка в GitHub Actions падает** — откройте вкладку Actions → последний
  запуск и посмотрите, на каком именно шаге ошибка; логи на английском, но
  обычно понятно, чего не хватает (чаще всего — это `flutter pub get` не
  может скачать зависимости или неверно указан `--org` в первом шаге).

## Что нужно обновить в Firebase при выкатке этой версии

Две вещи меняются на стороне базы — без них часть исправлений не заработает:

```bash
firebase deploy --only firestore:rules,firestore:indexes
```

1. **Правила** (`firestore.rules`) — добавлена коллекция
   `reservationSlots`. Это обезличенное зеркало занятости столов бронями:
   только `tableId`, интервал, признак «занимает» и uid владельца. Гостевое
   приложение читает именно его, потому что саму коллекцию `reservations`
   ему читать нельзя (там чужие имена и телефоны) — раньше из-за этого
   экран брони в «Колибри Лаундж» молча показывал «слотов нет», а выбор
   стола на карте не открывался вовсе.
2. **Индексы** (`firestore.indexes.json`) — добавлен составной индекс
   `inventoryMovements (itemId ASC, createdAt DESC)`. Без него история
   движений позиции склада отдавала случайные сто записей вместо последних.

Зеркало занятости и поле `tables.busyUntil` достраиваются автоматически при
первом входе сотрудника на POS после обновления — отдельная миграция
руками не нужна.

## QR-коды столов и установка приложения

В QR зашита ссылка `https://hoocah-pos.web.app/table/{tableId}` на страницу
из папки `public/`. Она мгновенно уводит гостя в приложение по
`kolibri://table/{id}`, а если приложения нет — показывает, откуда его
скачать (Яндекс.Диск и Google Диск).

Страница выкатывается вместе со всем остальным:

```bash
firebase deploy --only hosting
```

Firebase Hosting входит в бесплатный тариф Spark — платить не нужно.

**Про уже наклеенные коды.** Раньше в QR зашивалась сразу ссылка
`kolibri://table/{id}` — собственная схема приложения. Приложение
по-прежнему понимает этот формат, поэтому напечатанные раньше наклейки
работают как работали. Но подсказку об установке они показать не могут:
если приложения нет, телефону нечем обработать такую ссылку и никакой наш
код в этот момент не выполняется. Чтобы подсказка появилась, коды нужно
перепечатать с экрана Админ → QR-коды столов.

Как временное решение рядом со старыми наклейками можно повесить любой QR
на адрес `https://hoocah-pos.web.app` — это страница «установить
приложение» без привязки к конкретному столу.

## Работа на бесплатном тарифе Firebase (Spark)

**Cloud Functions разворачивать не обязательно.** Они требуют платного
тарифа Blaze, поэтому всё, что они делали, приложение умеет само — и по
умолчанию именно так и работает (флаг «Cloud Functions подключены» в
Админ → Профиль заведения выключен).

| Что делала функция | Кто делает без неё |
|---|---|
| Начисление кешбэка при закрытии чека | Касса на POS (`accrueBonuses`) — работало и раньше |
| Push смене: новая бронь, вызов гостя | Локальные уведомления POS (`SessionAlertsService`) |
| Авто-неявка: снять бронь, за которой не пришли | Фоновые задания POS (`BackgroundJobsService`) |
| Поздравления с днём рождения + подарочные бонусы | Там же, раз в сутки |
| Push гостю: бронь подтверждена, заказ готов, бонусы | Локальные уведомления в «Колибри Лаундж» (`KolibriNotifications`) |
| Push гостю за час до брони | Отложенное системное уведомление — работает даже при закрытом приложении и без сети |
| Прокси к tooken.club | Приложение читает ключ из `meta/aiSettings` (см. комментарий в `firestore.rules`) |

Фоновые задания POS выполняет «дежурный» планшет — тот, что первым взял
замок в `meta/jobsLock`. Три планшета в зале не сделают работу трижды.
Условие одно: хотя бы один планшет должен быть включён — то есть в рабочие
часы всё работает, а ночью брони разбираются утром, когда зал откроется.

Ограничение локальных уведомлений гостю: реактивные («заказ готов»,
«бронь подтверждена») приходят, пока приложение гостя живо или висит в
фоне. Напоминание за час до брони планируется в самой Android заранее и
срабатывает в любом случае.

### Если всё-таки подключите Blaze

Разверните функции и включите тумблер «Cloud Functions подключены» в
Админ → Профиль заведения — приложение перестанет дублировать серверную
работу, и гость не получит по два одинаковых уведомления:

```bash
firebase deploy --only functions
firebase functions:secrets:set TOOKEN_API_KEY
```

В самих функциях тоже исправлено: в `onSessionClosed` убрано двойное
начисление кешбэка (гонка между сервером и кассой), добавлен уровень
«Алмаз» (15%), а время в уведомлениях считается в часовом поясе заведения,
а не в UTC.
