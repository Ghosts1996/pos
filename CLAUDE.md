- **Защита от ботов и взлома** (`saas-gateway/shield.js`, тест `test.shield.js`, проверки в `test.auth-server.js`/`test.smoke.js`): каждый запрос к API до разбора проходит щит — с адреса больше 2000 запросов/мин → 429 до конца минуты, больше 6000 → бан 10 мин; пробы сканеров (`/.env`, `/wp-login.php`, `../`…) → 404, третья за 10 мин → бан на час; sqlmap/nikto/nuclei по User-Agent → бан сразу; 25 неверных паролей/кодов с адреса за 15 мин → бан 30 мин; 20 неверных паролей к одной почте за сутки (с любых адресов) → вход по паролю для неё закрыт на 12 ч (`auth/password-locked`, войти через «Забыли пароль?», письмо `passwordAttackLetter` хозяину почты, тревога админам в бот); пользователь прочитал >100 тыс. документов за 10 мин → тревога, >1 млн → 429; новых подключений к потоку данных >300 за 10 мин с адреса → 429. Повторный бан за сутки — вдвое дольше (до суток). Активные баны и замки почт (только хеши) — в `state/shield.json`, переживают перезапуск. Закрытому адресу кабинет и веб-версия гостя показывают «Доступ временно закрыт» с причиной (`zal-db.js` → `status.blocked`). Сводка «🛡 Защита» — в «🖥 Сервер» бота поддержки. **Сервер** (`saas-gateway/server-shield.sh`, вызывает `update-server.sh`, сторож — с `--quick`): fail2ban для SSH (5 ошибок за 10 мин → бан 1 ч, до суток), обновления безопасности Ubuntu сами в 10:30 по времени сервера без перезагрузки, sysctl против SYN-флуда и подмены, `/opt/saas-gateway/{state,backups,support-uploads}` — 700, `/etc/*-gateway.env` — 600, публично открытые порты баз (5432, 3306, 6379, 27017, 2375…) на внешнем интерфейсе закрываются цепочкой `ZALPOS-SHIELD` (Docker-порты только показываются); итог — `/var/lib/zalpos-shield/status.json`. nginx, Docker и sshd не трогает.

## 6. Открытые вопросы и известные ограничения

- **VPN:** с зарубежными серверами многих VPN сайт не открывается (VPN не пускают на российские сайты; с российским сервером VPN работает). Решение — исключение zalpos.ru в VPN; зарубежный посредник нельзя (152-ФЗ). Подсказка уже в боте менеджеров и в плашке `heal.js`.
- **8 умеренных уязвимостей** внутри firebase-admin — нужна мажорная версия, не трогали.
- **НПД:** лимит 2,4 млн ₽/год; бухгалтеру уточнить, подходит ли формулировка оферты «право использования программы» для НПД.
- **Пакет Android** оставлен `com.hookahpossaas` (менять только перед публикацией в сторах, по безопасному плану).
- **Защита — что учесть:** сам владелец, 5 раз ошибившись при входе по SSH, закроет свой адрес на час (вход через консоль хостинга работает). Пороги щита рассчитаны на CGNAT мобильных операторов — не снижать без причины. Касса (Flutter) на замок почты показывает общее «слишком много попыток» (код 429), текст сервера — только в кабинете. От большой DDoS-атаки один VPS не спасёт — нужна российская служба защиты от DDoS перед сервером (решение и оплата — за владельцем). nginx-лимиты (`limit_req`) не ставили: правило «update-server.sh не трогает nginx».
- **Карта:** своя карта и маршруты курьера работают с нашего сервера (`docs/delivery.md`, раздел 17). Кабинет («Доставка → Сейчас») и страница гостя пока без неё: нужен перенос файлов карты на zalpos.ru (поток карты должен быть с того же адреса, что страница). Первая сборка карты на сервере проверена только по частям (pmtiles, osmium, граф) — после первого запуска посмотреть `/var/log/zalpos-map.log`. Курьер службы доставки проверен только на подменённых ответах — первый реальный вызов делать тестовым.
- **Доставка, шаг 2** (см. `docs/delivery.md`, раздел 12): автоматические чеки кассы (предоплата 100% / полный расчёт при вручении), курьер в карточке кассы, цена доставки и районы в APK гостя (старые версии: базовая цена, «назовите при звонке»), геокодер для цены по расстоянию; строка о геолокации курьеров в политике ПД.
- **Не сделано из пожеланий:** запрет продажи в минус; SMS-канал для «Вернуть гостя» (нужен российский SMS-провайдер). Открытый API (только чтение) и «Вернуть гостя» — сделаны; промокоды и сертификаты уже были.
- **Проверка CI без gh-токена:** репозиторий публичный — `gh run list -R ghosts1996/pos`, `gh run view <id> -R ghosts1996/pos --log` работают и без входа; так проверять «Обновление сервера» и сборку кассы (`public-apk-release.yml` гоняет `flutter test` и сборку на каждый push в `lib/**`).
- **Локальный стенд в песочнице:** `TELEGRAM_SECRET_KEY` подписывает и входы — держите его постоянным между перезапусками, иначе сохранённые сессии гостя получат 401.
- **Песочница без npm:** тесты сервера можно гонять с заглушкой firebase-admin (только Timestamp/FieldValue/FieldPath) через `NODE_PATH`; `test.rules-local.js` (mocha) и тесты `pii-gateway` (pg) без пакетов не запускаются.
- У владельца на бумаге: подписать приказ № 1-ПД, порядок уничтожения, вести журнал обращений; дождаться номера РКН.
